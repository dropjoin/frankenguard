    SEC. 02

    The policy

    The rules the monster enforces. Change them and the ledger records the old value and the new one. Defaults are $250 per transaction, $500 per day, four fictional demo vendors, freeze off.

    Spending caps

    Whole dollars or cents, e.g. 250 or 250.50. Stored as integer cents.

    Recipient allowlist

    Exact names only. A payee not on this list is rejected, no matter how polite the memo.

    Freeze switch

    One switch. While frozen, every proposal is rejected before any other gate runs.

    Guard active

    Proposals are evaluated normally.

    Clears the ledger and policy stored in this browser, then re-runs the boot self-check.

    SEC. 04

    Anatomy of the monster

    Four parts stitched together. Each one does exactly one job, and each one is replaceable without touching the others.

    Part 01 · The mouth

    The Agent

    A deterministic intent parser reads plain-language instructions and extracts payee, amount, and invoice ref. It never guesses: what it cannot prove, it reports.

    src/parser.js · strict amount grammar · zero floats
    Part 02 · The brain

    The Rule Engine

    Six gates in fixed order: freeze, amount, per-tx cap, daily cap, allowlist, memo guardrail. Same inputs, same verdict, every time. No model in the decision path.

    src/engine.js · 6 gates · 9 injection patterns
    Part 03 · The memory

    The Ledger

    Every verdict and policy change lands in a SHA-256 hash chain. Verification recomputes every link and names the first entry that fails.

    src/ledger.js · SHA-256 · genesis-linked
    Part 04 · The leash

    Hooks + MCP

    Kiro agent hooks run the tests on save and verify before commit. An MCP server exposes the same engine to any agent, over stdio JSON-RPC, no network.

    tools/mcp-server · 3 tools · stdlib only

    Honest limits, stated plainly

    • No real money moves here. No wallet is connected, nothing is signed, no payment rail is called. Frankenguard approves or rejects proposals; execution is someone else's job.
    • The vendors are fictional. Acme Corp, Globex, Initech, and Hooli are demo data, not real businesses.
    • The parser is not an LLM. It is a deterministic grammar. It will fail on phrasing it does not understand, and it says so instead of guessing.
    • The daily cap resets at UTC midnight. Spending just before and just after midnight can total twice the daily cap within minutes. That edge is documented, not hidden.
    • Your data stays in your browser. The ledger and policy live in localStorage under one versioned key. Nothing leaves the page.
